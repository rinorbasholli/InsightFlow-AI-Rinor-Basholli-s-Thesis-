\chapter{Reproducing the results}
\label{app:eval}

This appendix explains how to run the laboratory and regenerate every result reported in Chapter~\ref{cha:eval}. Commands are run from the repository root.

\section{Environment}
\label{sec:run-env}

The adversarial results were produced on a CPU with PyTorch~2.14.1, as recorded in \path{adversarial_metrics.json}. The phishing result file records the Python and scikit-learn versions of its run; the phishing results were reproduced identically with Python~3.13 and scikit-learn~1.9.1. The dependencies in \path{eval/requirements.txt} are not pinned to exact versions. The batch script expects the CIFAR-10 test set under \path{eval/adversarial/results/cifar10/} and does not download it; starting the attack service once downloads it there through torchvision. The model weights are downloaded by \texttt{torch.hub} on first use.

\section{Running the laboratory}
\label{sec:run-web}

\begin{lstlisting}
cp .env.example .env.local
# set GEMINI_API_KEY, LAB_BASIC_USER and LAB_BASIC_PASS
# optional: GEMINI_MODEL, EVAL_API_URL, EVAL_INTERNAL_TOKEN
npm install
npm test
python3 eval/adversarial/service.py &   # attack service on port 8001
npm run dev                              # http://localhost:3000
\end{lstlisting}

For a production-style run, \texttt{npm run build} followed by \path{deploy/start-live-lab.sh} starts both processes and refuses to start without credentials. The container images are built from \texttt{Dockerfile} (web server only) and \path{deploy/Dockerfile.all-in-one} (web server and attack service).

\section{Phishing benchmark}
\label{sec:run-phish}

\begin{lstlisting}
python3 -m pip install -r eval/requirements.txt
python3 eval/phishing/run_benchmark.py
\end{lstlisting}

The script regenerates \path{eval/phishing/corpus.jsonl} from code and writes \path{phishing_metrics.json} and \texttt{predictions.csv} under \path{eval/phishing/results/}. It does not overwrite \path{MANUAL_REVIEW.csv}. The result file contains the hold-out results, five-fold cross-validation on random folds and five-fold cross-validation grouped by sender domain, together with the Git commit and library versions.

\section{Adversarial batch}
\label{sec:run-adv}

\begin{lstlisting}
python3 eval/adversarial/run_attacks.py \
  2>&1 | tee eval/adversarial/results/run200_full.txt
\end{lstlisting}

The script writes \path{eval/adversarial/results/adversarial_metrics.json}, including the commit and PyTorch version, and stops with an error if any perturbation exceeds its budget. The log of the reported run is \path{run200_full.txt}.

\section{Live attack calls}
\label{sec:run-live}

With the attack service running, the recorded live calls are reproduced with the following requests to the service API (targeted mode is available through the API only):

\begin{lstlisting}
curl -s -X POST localhost:8001/attack -H 'Content-Type: application/json' \
  -d '{"originalClass":"airplane","noiseLevel":0.05,"method":"fgsm"}'
curl -s -X POST localhost:8001/attack -H 'Content-Type: application/json' \
  -d '{"originalClass":"airplane","noiseLevel":0.05,"method":"pgd"}'
curl -s -X POST localhost:8001/attack -H 'Content-Type: application/json' \
  -d '{"originalClass":"airplane","targetClass":"bird","targeted":true,
       "noiseLevel":0.05,"method":"fgsm"}'
\end{lstlisting}
