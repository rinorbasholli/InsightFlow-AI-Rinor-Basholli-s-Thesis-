\chapter{Evaluation}
\label{cha:eval}

This chapter describes how I evaluated the laboratory and which numbers I can actually cite. I only use values from files that exist in the repository. If a file is missing, I write that the number is \textit{not yet exported}. I do not invent clean accuracy, robust accuracy, or attack success rate.

\section{What I evaluated}
\label{sec:eval-what}

I separated three kinds of output.

\begin{enumerate}
\item \textbf{Configuration.} Scores I assigned in templates. The dashboard 75\% and 51\% values belong here.
\item \textbf{Computed on a reconstructed corpus.} The phishing JSON in \texttt{eval/phishing/results/phishing\_metrics.json}.
\item \textbf{Computed on a real classifier.} The adversarial JSON in \texttt{eval/adversarial/results/adversarial\_metrics.json}. The file now holds the 200-image FGSM/PGD run (seed 20260927). I cite only those exported fields.
\end{enumerate}

I also ran \texttt{npm test} and I read the \texttt{source} field in \texttt{server.ts}.

\section{Dashboard values are configuration}
\label{sec:eval-a3}

A3 in the supervisor action list is explicit. The 75\% and 51\% figures are not findings.

When I click ``Load Study Dataset (90 Samples)'', \texttt{generate90Samples()} fills realism and detectability from the bands in Section~\ref{sec:impl-phish}, using seed 20260927. The dashboard uses \texttt{Math.round} on those means. For that seeded load the rounded values are 75\% mean designed realism (raw mean $75.12$) and 51\% for $100$ minus mean AI-class detectability (raw $51.23$). Those are still configuration. They are not filter measurements.

I wrote those bands so that conventional rows look easy to spot and AI-style rows look harder. That is a teaching design. It is not a measurement of a mail filter, a clinical pilot, or a sample-size study. I deleted that kind of language from the user interface. I do not use it here.

The dataset is in-memory templates. It is not a mailbox harvest.

\section{Phishing benchmark}
\label{sec:eval-phish}

I wrote \texttt{eval/phishing/run\_benchmark.py}. The first corpus was 288 repeated templates and the classifier reached F1 $= 1.0$. That score was a construction error, not a result, so I rebuilt the set. Ham and phish now share the same stems and differ mainly in the last instruction.

An earlier export concatenated \texttt{From:} plus the sender into every TF-IDF string while the JSON still said the sender was held out. That note was false. I now train \emph{both} feature sets on the same 187 rows and report the gap. Table~\ref{tab:phish} is the 70/30 split (\texttt{random\_state=20260927}) used for \texttt{predictions.csv}. Table~\ref{tab:phish-cv} is five-fold stratified cross-validation on the full set. A constant ``always phish'' dummy is the trivial baseline. I do not treat the numbers as Gmail or SpamAssassin performance.

Bodies still contain URLs and lookalike hostnames, so \texttt{wording\_only} is not domain-free. It only drops the From line.

\section{Adversarial method}
\label{sec:eval-adv}

I implemented the method my supervisor asked for: FGSM and PGD~\cite{goodfellow2015explaining,madry2018towards}, on at least 200 images, with clean accuracy, robust accuracy, attack success rate, and perturbation size. I do \emph{not} cite torchattacks numbers~\cite{kim2020torchattacks}. The batch script and the live service use the same pixel-space clip in \texttt{run\_attacks.py} so measured $L_\infty$ stays $\le \varepsilon$.

\texttt{eval/adversarial/run\_attacks.py} does the following.

\begin{enumerate}
\item Download the CIFAR-10 test set~\cite{krizhevsky2009cifar}.
\item Draw $n=200$ indices with \texttt{numpy} RandomState seed 20260927.
\item Load \texttt{cifar10\_resnet56} from \texttt{chenyaofo/pytorch-cifar-models}~\cite{chenyaofo2021cifar}.
\item Measure clean accuracy.
\item For $\varepsilon \in \{2/255,\ 8/255,\ 16/255\}$, measure FGSM and PGD robust accuracy, attack success rate (label flip among images the model classified correctly before the attack), and mean $L_\infty$.
\item Write \texttt{eval/adversarial/results/adversarial\_metrics.json} with \texttt{source: "computed"}.
\end{enumerate}

The JSON now has \texttt{n=200}, clean accuracy $0.955$ (191 of 200 already correct), seed 20260927, \texttt{source: "computed"}, torch $2.14.1$, and git commit \texttt{742a669}. Table~\ref{tab:adv} copies the three $\varepsilon$ buckets. ASR is a label flip among those 191 clean-correct images; \texttt{flip\_rate} is the old all-image figure. Each robust accuracy has a Wilson 95\% interval. $L_\infty$ never exceeds $\varepsilon$. The full stdout is \texttt{eval/adversarial/results/run200\_full.txt}.

These numbers are for CIFAR-10 ResNet-56 on 200 test images, not for ImageNet ResNet-50. PGD at $8/255$ and $16/255$ flipped every clean-correct image in this subset. That is a strong attack on this model and this budget, not a claim about every classifier.

The live Simulate button is a single-image call to \texttt{POST /attack}. Default is untargeted. Targeted runs only when the request sets \texttt{targeted: true}. The service uses the same clip as the batch and refuses $L_\infty > \varepsilon$. Recorded calls are \texttt{eval/adversarial/results/live\_fgsm.json}, \texttt{live\_pgd.json}, and \texttt{live\_fgsm\_targeted.json}; each has \texttt{noiseStrength} $0.05$ at $\varepsilon=0.05$. I do not copy those one-image scores into Table~\ref{tab:adv}.

The tab shows a fixed label: ResNet-56 (CIFAR-10, pretrained). Unknown class names return HTTP 400.

\section{Unit tests}
\label{sec:eval-tests}

I ran \texttt{npm test}. The files \texttt{tests/labSecurity.test.ts} and \texttt{tests/apiContract.test.ts} check string comparison, fail-closed credentials, the login cookie, the injection regex, the 10/40 rate limits, the 32\,kb body cap, and the four documented \texttt{source} labels. They do not measure phishing F1 or ASR.

\section{What I did not evaluate}
\label{sec:eval-not}

I did not run a user study. I did not measure Gmail catch rates. I did not score real videos. I did not compare ImageNet ResNet-50 with CIFAR ResNet-56 in a second metrics file. I did export one labelled Gemini session in \texttt{eval/gemini\_runs/SUMMARY.json} (three teaching routes). Computed attacks are logged under \texttt{eval/adversarial/results/live\_*.json}. Those files are single sessions, not a production traffic count.
